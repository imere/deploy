# 假测试信号清单

## A 类 · 断言回显输入（error）

```js
const plan = makePlan(fixture)
assert.deepEqual(plan.input, fixture)   // 把输入原样又断言一遍
```

## B 类 · mock 掉被测主体（error）

把被测函数替换成 stub，再断言 stub 的返回值。测的是 stub 不是实现。

## C 类 · 只断言「不抛」（warning）

`fn(x)` 不写任何断言，靠「抛了就失败」。有效但弱：静默做错的那类 bug 抓不到。

## D 类 · assert.throws 第二参传字符串（error）

```js
assert.throws(fn, '非法变量名')   // Node 的第二参是错误对象/类/校验函数，传字符串按名字匹配，匹配不上也会通过
```

## E 类 · 零断言块（error）

一个 `test()` / `it()` 块里一条 `assert.` 都没有。

## F 类 · 类型收窄当断言（info）

`assert.ok(x)` 紧跟 `assert.match(x.field, ...)` 是正常的收窄写法，不是假测试——别误杀。

## G 类 · 被忽略的校验参数（error）

实现里收了参数但从没读过。测试喂了各种值全绿，因为压根没参与判定。查法：看函数签名里每个形参在函数体里有没有出现。

## H 类 · 哨兵测试（info，合法）

`assert.fail('需要 X 后手工启用')` 放在 skip 块里是有意为之，用来占位提醒——不算假测试，但要确认它确实在 skip 块里。

# 机械扫描的写法

1. 遍历测试文件，按 `test(` / `it(` 行起、括号配平切块
2. **先扫文件内的 helper 定义**，收集「内有 assert 或 sentinel throw」的名字——跳过这步会把 helper 调用全判成零断言，实测全是误报
3. 块内断言数 = 内联 `assert.` + helper 调用
4. 逐类匹配上面的信号

# 覆盖率凑数

覆盖率只能证明「这行被执行过」，证明不了「这行被测过」。

- **有门槛的包才有凑数动机**，从那里查起（没有门槛的包没人会去凑）
- 报告要给每条 `文件:行号` 与为什么，拿不准标「可疑」
- 覆盖忽略注释：先证明项目里确实有这个忽略机制再去找它，别凭印象搜
- 硬证据是变异得分，不是覆盖率数字

# 验收脚本

独立验收脚本（`.tmp/accept-<主题>.mjs`）用来证明链路真能跑，它自己也要守规矩：

- 放临时目录，**不入库**——它是一次性的证据不是资产
- 直接 import **构建产物**（不是源码），验的是真正会跑出去的东西
- 断言失败要带上实际值
- 跑完不留痕，目录里不该多出东西

**写断言前先探明契约**（实测踩过三次，猜契约会全盘错）：

- 这个函数是抛错还是返回码？（断言「退出码 3」而函数其实抛错 → 全错）
- 输出走 `write` 回调还是 stdout？（断言 stderr 而信息在 stdout → 断言空）
- 哪些参数必填？（漏传必填导致报的错和要验的错不是同一个 → 误判成实现有问题）

要断言的东西：契约（返回码/退出码/输出分流）、边界（歧义靠拒绝、缺省值来源、超限报错而非静默截断）、失败路径（注入会失败的实现，断言错误码与提示）。
