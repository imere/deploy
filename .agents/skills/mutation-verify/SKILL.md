# 变异验证

## Step 1 · 定向验证（单条，成本一分钟）

修完一个 bug、补完一条回归测试之后立刻做：

1. 撤掉修复（把代码改回错的样子）
2. 跑那条测试
3. **变红** → 这条测试真的守着这个行为
4. **仍全绿** → 这条测试是摆设，**重写**（不是删掉——说明该行为根本没被测到）

子代理交回的测试一律视为未经验证，先跑一遍再看。

## Step 2 · 规模化跑全池

确认跑完了整个候选池，不要抽样。抽样确定的话，另外那批永远不会被看到——实测抽样 20 个时全绿，跑完 38 个立刻冒出 3 个存活，每一个都对应一类「只测了一半」的假测试。

```bash
node scripts/mutate.mjs --package <pkg> --max all --fail-over <阈值>
```

变异方向要挑有代表性的，尤其是「静默做错」那类——比「直接崩」更危险。

## Step 3 · triage 存活清单（gate）

**先 triage 存活清单，不要先调阈值。** 每一个存活都要判定属于哪一类：

- **测试缺一半**：只测了类型不对没测值不合法、只喂了非法值没喂合法值、A 处有判据 B 处没有 → 补测试
- **等价变异**：改了行为完全相同（如 `<` 改 `<=` 而边界永不命中）→ 登记豁免

## Step 4 · 登记等价变异

豁免清单每条必须有 `file` / `line` / `label` / `reason`，**缺 reason 就拒收整份清单**。三者合起来才唯一确定一处候选，只记位置会把同一行的不同变异混在一起。

已登记的豁免要定期复查：把它真的改一遍跑一次——

- 还绿 → 豁免成立，不计入存活分子（分母也排除，否则会稀释存活率）
- 变红 → 计为杀死并标「清单过期」，**这一步要失败**：留着不会让数字失真，但会让清单变成骗人的东西
- 一次都没匹配上 → 多半是产物行号变了，那处已回到统计里，单独报出来

## Step 5 · 收阈值

1. 先跑一轮拿基线（抽样必须是确定的：产物文件排序 + 包间轮转，别用随机）
2. 把阈值收到基线之上一点点，给「新出现的、还没登记的等价变异」留一个的余量
3. 之后首红仍然先 triage，不先调阈值

## 与其他 skill 的分工

`fake-test-audit` 做静态排查（恒等断言、零断言这类根本不会失败的测试），本 skill 做动态验证，两者互补。
