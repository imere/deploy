# 变异验证：撤掉修复，测试必须变红

覆盖率高不等于行为被验证。**证明一条测试有用的唯一办法是让它失败一次。**

## 1. 做法

只改构建产物，**不动源码**（改完必须还原并重建，别把变异留在源码里）：

```bash
cp <pkg>/build/<file>.js .tmp/x.bak
# 用脚本改掉产物里那行修复
<测试命令> <pkg>/build/<那个>.test.js    # 必须变红
cp .tmp/x.bak <pkg>/build/<file>.js && <构建命令>   # 还原并重建
```

写一个 `.tmp/mutate-<主题>.mjs`，每个方向一个正则对 + 一个 `restore` 子命令，
循环跑：`变异 → 跑单包测试 → 跑独立验收脚本 → 还原`。两个都绿才算漏网。

## 2. 变异方向的选择（最容易做错的一步）

**变异要往「与正确实现只差一点点」的方向做，并且要先问：**
**「这个变异在当前夹具下，算出来的结果和正确实现一样吗？」一样就换夹具。**

实测踩过：修的是「撤销目录时登记最外层原本不存在的那级」，写了条「不许误删上一轮影子目录」的测试，
再变异成「删整条链最外层」—— 结果**全绿**。因为夹具里那个目录本来就存在，两条路径算出同一个结果，
测试根本没区分它们。补了「目录都是本轮刚建的」那个用例才卡住。

同一种修复往往要做 **2~3 个方向**才算验过：
- 漏做（该做的没做）
- 多做（不该做的做了）
- 记错状态（做对了但对外报的状态错）

**还要检查假实现自己有没有把你验的东西做掉了。** 实测踩过：验「close 幂等」，
把 `if (closed) return` 那道 guard 删掉（不幂等），独立验收**没抓到** ——
因为假 client 的 `end()` 自己也做了「已关就不再记」的幂等，重复关闭被它吞了。
改成「记录每一次调用」之后才变红。
教训：**假实现要尽量笨**（只记录、不加自己的健壮性），否则它替被测代码把缺陷挡住了。

## 3. 判定

- 撤掉修复后测试**变红** → 这条测试真的守着这个行为
- 撤掉后**仍全绿** → 这条测试是摆设，重写（不是删掉 —— 说明该行为根本没被测到）

**注意区分「变异没生效」和「测试没抓到」**：先确认产物里的目标字符串真的被改掉了
（正则里多写了个引号就会静默不命中，这时「全绿」是假象）。让脚本在没命中时明确报「未命中」。

## 4. 什么时候做

- 每修完一个 bug、补完一条回归测试（成本一分钟，收益是知道这条测试有没有用）
- 子代理交回的测试一律视为未经验证，先跑一遍变异再看
- 怀疑某片测试形同虚设时，做一轮批量变异找盲区

## 5. 局限

变异验证通过 ≠ 覆盖面够。它只能证明「这一处改动被抓到」，
证明不了「所有该测的都测了」。所以：
- 变异方向要挑**有代表性的**（尤其是「静默做错」那类，比「直接崩」更危险）
- 配合 `fake-test-audit` 做静态排查，两者互补
