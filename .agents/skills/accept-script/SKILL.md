# 独立验收脚本

**实现方自己的测试不算验收。** 它可能为了通过而放宽断言，也可能测的是它自己写的 helper。
验收要另写一份脚本，只断言**可观测行为**。

## 1. 落点与形态

- 放临时目录（如 `.tmp/accept-<主题>.mjs`），**不入库** —— 它是一次性的证据，不是资产
- 直接 import **构建产物**（不是源码），这样验的是真正会被跑出去的东西
- 一组 `ok()` / `eq()` 断言，全部跑完打印计数；失败要**带上实际值**

## 2. 断言什么

- **契约**（返回码、退出码、输出分流：stdout vs stderr vs 日志）
- **边界**（歧义靠拒绝、缺省值从哪来、超限时报错而不是静默截断）
- **失败路径**（依赖注入一个会失败的实现，断言错误码与提示）
- **不留痕**（跑完之后目录里不该多出东西 —— 见「验收脚本自己不许弄脏机器」）

不要断言实现细节（内部调用了几次、用了哪个私有函数）—— 那会让重构变成改测试。

## 3. 先探明契约再写断言（实测踩过三次）

脚本自己写错前提比被测代码有 bug 更常见。写之前先用一次**探针脚本**确认：
- 这个函数是**抛错**还是**返回码**？
- 输出走 `write` 回调还是 stdout？
- 哪些参数是必填的？

实测教训：
- 断言「返回退出码 3」，而函数其实是**抛错**（退出码由顶层转换）→ 断言全错
- 断言「stderr 里有 X」，而错误被内部接住、信息在 stdout → 断言空
- 漏传必填参数导致报的错和要验的错不是同一个 → 误判成实现有问题

## 4. 验收脚本自己不许弄脏机器

实测：脚本里用默认依赖跑「真的落盘」那条断言，结果把发布目录写进了**真实用户目录**。
**验收不该在开发机上留痕。**

规则：
- 起临时目录，把「家目录 / 应用目录 / 状态目录」都指向它
- 或者干脆改断言：从「检查目录出现了」改成「检查输出里说了会写到哪」
- 跑完检查临时目录之外有没有多出东西

如果确实需要真跑：先看清默认路径是什么，跑完立刻清理并复查。

## 5. 与变异验证配套

验收脚本写完后做一轮 `mutation-verify`：撤掉修复 → 脚本也必须变红。
只有单测变红而验收脚本不变红，说明验收断言没打到点上。
