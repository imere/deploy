# 覆盖率的诚实度：执行过 ≠ 测过

## 1. 先认清楚覆盖率能证明什么

`node --test --experimental-test-coverage` 报 100%，只说明每个可执行行都被**求值过**。
它不说明任何一行被**验证过**。一个什么都不断言、只是把函数挨个调一遍的测试，
覆盖率同样是 100%。

所以「某包覆盖率 100%」永远不能直接当质量结论，只能当**提问的起点**：它凭什么到 100%？

## 2. 有门槛的包才有凑数动机 —— 从那里查起

覆盖率门槛写在 `scripts/check-coverage.mjs` 顶部的 `GATED` 表里。
**受门槛的包才是凑数动机最强的地方**，没门槛的包（IO 层）数字高低都没有人在追。

实测的一个分布：

| 包 | 覆盖率 | 是否有门槛 |
| --- | --- | --- |
| `schema` / `core` / `template` | 100% | **有** |
| `ssh` 82% / `local` 82% / `transport` 84% | 8x% | 无 |

查的时候**必须带上对照组**：抽两三个**没门槛**包的测试文件读一遍，比断言密度与校验强度。
只有当「受门槛的包明显比不受门槛的包弱」时，才能说这是门槛逼出来的；
如果两边基线一样，说明断言写得好是本仓的基线，不是数字逼的。

## 3. 要查的形态，与实测的信噪比

一次全量审计（13 个测试文件 / 178 个用例逐个读 + 10 类形态机械探测）的实测结果：

| 形态 | 机械命中 | 其中确属问题 | 结论 |
| --- | --- | --- | --- |
| **恒等断言**（两边归一化后逐字符相同） | 1 | **1** | **值得做判据** |
| 断言回显输入（`assert.equal(f(a), a)`） | 2 | **0** | 命中全是合法契约（字面量匹配器、不误伤无变量输入），别加 |
| 重复用例只换参数（归一后用例体同形） | 9 | **9 条全是误报** | **噪声大于价值，明确不要加** |
| 复制实现当期望值 | 0 | 0 | 判据留着，成本低 |
| 覆盖忽略注释 | 0 | 0 | 见 §5 |

**加判据之前先量信噪比。** 一个命中 9 条、9 条全假的探测，加进门禁只会把真问题淹掉 ——
这正是 `check-tests.mjs` 文件头那句「报告工具自己有噪声，它的输出就没人看」。

## 4. 变异得分才是硬证据

静态探测只能说「这条用例长着什么形状」，说不了它对错。
真正区分「执行过」与「测过」的是**变异**：改坏源码，测试还绿 = 这条用例是摆设。

实测佐证：`template` 包 8 个变异（布尔翻转）**全部被杀死，存活 0** ——
那个包的 100% 与测试有效性是一致的。反过来说，
**覆盖率 100% 而变异存活率高**，就是「执行过但没测到」最硬的证据，比任何静态扫描都硬。

跑变异注意：它只在 `.tmp/` 的副本上改，**绝不碰真实 `build/`**；
跑完要自检产物字节数没变（实测过：612 个文件 / 4108332 字节，跑完一模一样）。

## 5. 覆盖忽略注释：先证明确实存在这个机制再去找

Node 的覆盖率忽略注释写法（`/* node:coverage ignore next */` / `/* node:coverage disable */`）
**不要凭印象 grep**。先写一个探针文件，用 `--experimental-test-coverage` 实测它是否生效
（6 个函数只调 2 个、加了注释之后仍报 100%），确认机制可用再去扫全仓。

同样的道理适用于 c8 / istanbul 的旧写法（`@ts-expect-error`-风格的 `/* c8 ignore */` 在
Node 内置覆盖率下**不生效**）—— 把两套字符串都 grep 一遍，但结论要以实测为准。

## 6. 判定的纪律

- 每条都要给 `文件:行号` 与为什么；拿不准就标「可疑，待人工判」。
- **不许乱扣帽子，也不许为了显得干净而放行。**
- 「没发现凑数」必须是**查过之后**的结论，要写明查了哪些、怎么排除的 —— 不查而说没发现，等于没查。
- 发现真问题**不要自己顺手改测试断言**（那是另一个任务的授权范围），列出来交给负责人。
