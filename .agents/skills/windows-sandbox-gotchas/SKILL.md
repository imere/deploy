# Windows / 沙箱环境坑

这些坑的共同点：**报错看起来像代码或依赖坏了，实际是环境**。
排查时先看报错原文里有没有环境侧的关键字，再决定要不要改代码。

## 1. 批量删除被安全护栏拦死

现象：node 的 `rmSync`、PowerShell 的 `Remove-Item` 都删不掉，报
单轮上限（如 50 个）或状态锁超时。

- **不要为此关掉安全护栏**，也不要用递归强删去绕过
- 换 git bash 的 `rm -f` 实测可删，但要**分批**（每批 40 个左右）循环，别一次上千
- 每批后核对剩余数量，删完复验一次

## 2. node 无法派生某些子进程

现象：`execFileSync('git', ...)` 报 `EBUSY`（errno -4082），
换绝对路径也一样；但在 shell 里同样的命令完全正常。Go 程序内嵌的实现不受影响。

**结论：需要调外部命令的脚本，改成「shell 负责调用、结果管道给 node 读 stdin」**，
node 端零子进程。排查时别误判成 PATH 问题 —— 换绝对路径一样失败。

## 3. 测试并发起不来

现象：测试运行器报「worker 启动失败 / 等待 worker 响应超时」，
多个文件全失败且显示「没有用例」。**这不是用例坏了。**

- 加单线程参数（如 `--no-file-parallelism`）实测可全绿
- 某些 pool 模式在本机完全不可用，默认（forks）才行

## 4. 构建卡在清空产物目录

现象：构建工具在 `prepareOutDir → emptyDir` 阶段挂住，
报删除垫片超时。因为清空目录走了 §1 那条被护栏劫持的删除路径。

修法：构建前先用 shell 的 `rm -rf <产物目录>`（bash 的 rm，别用 node），清理后构建正常。

## 5. 沙箱造成的假失败

跨包测试、真起子进程的用例在沙箱下会：
- 拦临时目录写入与产物读取
- 让单个用例跑 80~130 秒，整体超时

**全量测试要关沙箱跑。** 一批失败同时出现、且都涉及 IO/子进程时，先关沙箱复跑再判断。
实测过 21 个「失败」全是环境造成，关沙箱即 0 fail。

## 6. 通用排查顺序

1. 报错里有没有环境关键字（安全删除垫片名、锁超时、`EBUSY`、worker 超时）
2. 单跑那一个用例 / 那一个包，是不是就通过了
3. 关掉沙箱复跑
4. 以上都无效，才怀疑代码

**不要先改代码。** 为环境现象改代码会引入真 bug，而且掩盖了真实原因。
