# 派发 prompt 模板

```
# 任务

<一句话：要做什么，产出什么>

# 背景

- 项目：<是什么项目>
- 这块在分层里的位置：<哪个包 / 哪个模块>
- 依赖方向：<谁能依赖谁，谁不能>

# 必读文件（编码前先读，每条带「为什么」）

- `packages/<pkg>/src/xxx.ts` —— <为什么必读>
- `packages/<pkg>/src/xxx.test.ts` —— <现有测试覆盖了什么，别重复造>

# 锚点

- 结论出自 `xxx.ts` 第 N 行：<那行是什么>
- 已经判过：<谁错了、谁是对的>

# 依据

<是约束反推出来的，还是实测出来的；实测的话给命令与输出>

# 边界

- 允许且只允许改：`packages/<pkg>/**`
- 不许跑 git（commit / add / push 由我做）
- 不许加依赖、不许跑 `pnpm install`
- 只许修被测试暴露的真 bug，不许为过测放宽断言
- 新码用的错误码必须是登记过的

# 禁项（会被 grep 卡住）

- `console.log`
- 注释里出现文档文件名或章节号引用（写依据就地把事实写清，或指向某个函数/常量）

# 完成后汇报

- 改了哪些文件、每个文件改了什么
- 你跑过的验证命令与结果（没跑过的写「未验证」）
- 不确定的点，列出来，不要猜
```

# 为什么 prompt 要这么啰嗦

子代理看不到当前对话，也不会主动去翻上下文。缺一样就会：

- 缺背景 → 它按通用最佳实践写，与本仓分层冲突
- 缺锚点 → 它自己找一个看起来像的地方改，改错文件
- 缺依据 → 它把「我觉得应该是这样」当需求实现
- 缺边界 → 它顺手改别的文件、顺手加依赖、顺手放宽断言
