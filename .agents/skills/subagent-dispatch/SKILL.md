# 派活与验收

## Step 1 · 调用姿势（先确认，不然会卡住）

- 子代理 CLI 通常不在默认 PATH，用包管理器的 `prefix -g` 查全局 bin 目录
- **直接跑不带子命令会进 TUI 卡住**，必须用一次性执行的子命令
- prompt 很长先落盘成文件，多行 prompt 用 stdin 传
- 长任务**后台跑**，不要前台等
- 汇报要落盘（`-o` 之类的输出参数），别只靠 stdout——管道截断会丢信息

## Step 2 · 写 prompt（模板见 `references/dispatch-template.md`）

prompt 必须自带全部上下文，子代理看不到当前对话。必带四样：

1. **背景**：项目是什么、这块在分层里的位置、依赖方向
2. **锚点**：结论出自哪个文件的哪一行（不是「某个文件里」）
3. **谁已经错了、谁是对的**（如果你已经判过）
4. **依据**：是约束反推出来的，还是实测出来的

外加本仓边界（下节）与禁项 grep。

## Step 3 · 声明边界（缺一条就会被越权改）

- **不许跑 git**：commit / add / push 全部由我来做
- 可改范围写死成 `packages/<pkg>/**`，不许改别的
- 不许加依赖、不许跑 `pnpm install`
- **源码只许修被测试暴露的真 bug**，不许为过测放宽断言
- 并发改同一个文件时要求**末尾追加**（并发改必冲突）

## Step 4 · 验收（顺序不能反）

1. **构建**——第一步永远是构建。子代理常被禁止跑构建，改完测试就走，留下类型错误
2. 跑受影响包的测试
3. 跑门禁
4. 变异验证（子代理交回的测试一律视为未经验证）
5. 只看 diff：查范围蔓延、查新增字段有没有人真的用

**「它是这么汇报的」不算证据。**

## Step 5 · 本仓禁项 grep

- `console.log` / 静态 `import 'ssh2'` / `execShell` / 纯包里的 `node:fs`
- `§` 与文档名——**先把注释剥掉再匹配**，包头纪律里常写着「本包不用 X」这类会被误伤的话
- 私有环境（仓库路径 / 代理端口 / 用户名 / token）
