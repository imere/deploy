# 派发子代理与验收

核心立场：**子代理负责写代码，你负责验收与全部 git 操作**。它的自述「已完成」不算数。

## 1. 调用姿势（非交互）

- 子代理 CLI 通常不在默认 PATH，用全局 bin 目录（各机不同，用包管理器的 `prefix -g` 查）。
  **别把查出来的盘符写进仓库** —— 一换机器就失效，还属于本机环境泄露。
- **直接跑不带子命令会进 TUI 卡住**，必须用一次性执行的子命令（如 `exec`）。
- prompt 很长 → 先落盘成文件，再用 `"$(cat 文件)"` 传（反引号/`${}` 不会被 shell 二次解析）。
- 长任务**必须后台跑**，不要前台等。
- 汇报要 `-o` 落盘，别只靠 stdout（管道截断会丢信息）。

## 2. 必读清单（强制写进 prompt 第一节）

子代理不知道本仓约定。不给清单它就会瞎猜，还会把读过的内容复述一遍（烧的是你的 token）。
每条写成「读它 + **为什么读**」：

| 该读什么 | 为什么 |
|---|---|
| 仓库纪律文件（AGENTS.md / CONTRIBUTING） | 铁律与工程约定 |
| 共享 types / 契约包 | 错误类型、核心接口 |
| **同层的参照实现** | 照它的风格与抽象层次写（比任何文字描述都有效） |
| 对应设计文档 | 标注了「实测」的部分是硬约束，不是参考意见 |
| 配置字段的真实形状 | 避免它编造不存在的字段 |

要求它动手前读完；**「我没读过 X」等于返工**。

### 派发前先把语义钉死（最容易被跳过，代价也最大）

如果你已经搞清楚了某件事的**语义**（例如「这个字段的最后一跳是目标机」），
**不要**指望它读一遍代码自己得出同样结论 —— 它会按自己的理解重新推断一遍，
而那份理解常常和你的不一样，且两边都能通过各自的测试。

在 prompt 里单开一节（例如「背景：已确认的事实，不要重新推断」），写进去：

- 语义结论本身，一句话
- **锚点**：结论出自哪个文件的哪一行（`hop-chain.ts` 第 20 行这种）
- 谁已经错了、谁是对的（如果你已经判过）
- 依据是什么：约束反推出来的，还是实测出来的

实测对比：同一件事派两批，第一批只给了必读清单 → 两个实现对同一字段的解释相反，
各自测试全绿；第二批给了锚点并判过谁对 → 一次通过。

顺带一条：**语义层的修复自己做完再派**。让它同时改「定义语义的包」和
「接线的包」，它会在两边各写一套自洽的解释。地基自己打，接线交给它。

## 3. prompt 骨架

1. **背景**：项目是什么、这块在分层里的位置、依赖方向
2. **铁律**：逐条抄进去（不要写「见文档」，它不会去翻）
3. **允许改什么 / 绝对不许改什么**
4. **详细规格**：API 形状、错误码、边界行为 —— 越具体越好，别让它自由发挥
5. **注入点**：凡是要测「失败路径」的地方，规格里必须写明依赖可注入（见 §6）
6. **测试要求**：纯函数单测 / 假实现契约测试 / 真机测试默认跳过
7. **验收命令**（让它自己跑通再交回）
8. **汇报格式**：文件清单 + 测试数（前 → 后）+ 工作区状态 + 设计取舍 + **没做到的点**

## 4. 边界（每次写死）

- **不许跑 git**（commit / add / push 全部你做）
- 不许改其他包、不许加依赖、不许跑安装命令
- 共享契约文件只允许**末尾追加**（并发改动必冲突）
- 源码只许修**被测试暴露的真 bug**，且要写清「原行为 → 为什么是 bug → 改成什么」；
  **不许为了让测试通过放宽断言**（要放宽得说明理由，由你拍板）
- **注释纪律**：注释只写「为什么这么定 / 不这么定会怎样」，不许复述代码；
  **不许引用文档章节号或文档名**（「见 x.md §3」）—— 章节号会漂移，读代码的人手边没有文档。
  要依据就**就地把事实写清**，或指向代码里的某个函数/常量。

## 5. 验收（你自己做，不看它的自述）

**第一步永远是构建**（不是测试）。实测过：子代理汇报「全部完成、错误码都齐了」，
而编译器有 16 个错 —— 它新加的错误码没进联合类型，它自己根本没跑通构建。

```bash
<构建命令>      # 0 error 才算开始
<全量测试命令>  # fail 必须为 0
```

再抽查：

- **先 `git status` 盘点它到底改了什么**，尤其当它报 failed 时 —— 实测多次：汇报文件没落盘、
  但代码已经写完在盘上。**别看到 failed 就重派**（会撞车）。
- 禁项 grep：裸打印、被禁的静态依赖、纯包里出现 IO 模块
- **禁项 grep（必查）**：章节号 `§` 与文档名。派发时写进边界能省一轮返工。
  清理时**先把注释剥掉再匹配**：包头纪律里往往写着「本包不用 X」，直接全文件匹配必然误报。
- **私有环境**：绝对路径 / 代理端口 / token / 用户名（见 `repo-sanitize-history`）
- **「带了但没人消费」的字段**：翻一遍新加的 detail/context 字段，逐个确认有代码真的读它。
  实测抓到某字段只进了 detail、全仓无人消费 —— 下一轮就会有人另写一套判定，于是同一件事有两处实现。
  判定要**收口在纯函数侧**，执行器只传参。
- **注释与实现是否相符**：实测抓到注释声称「端口要显式写 22」而实现没写。
  两者不符时，按**既有约定**判断哪个对，别默认改实现。
- **写一份独立验收脚本**断言行为，不采信它的测试（见 `accept-script`）
- 注释是「解释为什么」还是「复述代码」—— 后者删

## 6. 规格里必须钉死「注入点」

子代理写的测试最大的问题是**测不了失败路径**，因为依赖是硬编码的。
凡是「要断言它在 X 失败时的行为」，规格里必须写明：

```
deps?: { load?: () => Mod; remove?: (p: string) => Promise<void>; clock?: () => number }
```

没有注入点的后果：该路径只能在真机上触发，于是永远没人测；
或者它为了测而改成「抛异常就算过」，等于没测。

## 7. 已知故障

| 现象 | 处理 |
|---|---|
| `terminated. Retry after the connection recovers.` | 运行时掉线，非代码问题。**先盘点残留产物** → 用续跑参数接着跑 |
| `<task> cancelled` + 删除工具超时 | 它清理临时目录时被安全护栏卡住，拖垮了进程。同上 |
| `Runtime shutdown did not complete cleanly` + 沙箱拒写用户目录 | 它在写自己的会话/日志目录被拦。**先盘点**，很可能代码已落盘。派发时关闭沙箱可避开 |
| 报「未登录 / 凭据失效」 | 凭据文件被清空。用**无浏览器**的登录命令刷新（默认会拉起浏览器窗口，在自动化里是灾难） |
| `..._conflict_migration_failed:lock` | 上次被掐死的进程留下的锁。**再跑一次就好**，不要去删锁文件 |
| 报 failed 但工作区干净 | 先探活再决定：发一个「回复 PONG」的最小任务。排查顺序固定 **探活 → 无浏览器登录 → 再探活 → 才重派**。别因为它挂了就改派另一个子代理（撞车 + 烧另一份配额） |
| 全量测试突然冒出一批跨包失败 | **先看是不是沙箱**：它会拦临时目录写入与产物读取，还会让真起子进程的用例单个跑 80~130 秒。实测一批失败全是环境造成，关沙箱复跑即 0 fail。**不要去改代码** |
| 单次跑 15 分钟以上 | **拆小**：先源码、再测试、再收口。每轮目标 ≤ 10 分钟 |
| 一次派两个子代理 | **绝对不要**。会同时改共享契约文件、并发构建打架 |
| 同一个包先后派两个（前一个没停） | 更糟：产出**两套设计叠加的半成品**（两个加载模块、孤儿文件、构建错）。派发前先确认没有在跑的同包任务；发现撞车就停掉后发的，再派一个「收敛」轮：指定保留哪套、删掉孤儿模块对 |

## 8. 产出物的常见病

1. **注水**：注释复述代码、文档写大片套话、为了「要注释」而注释。只留「为什么不这么定会怎样」。
2. **泄露私有环境**：本机路径、代理端口、token、用户名写进文档或注释。提交前 grep，命中就参数化。
   注意区分：可复现的实验靶机地址不算泄露，本机**开发**环境才算。
3. **用类型 cast 假装接上了不存在的字段**：`(cfg as { readonly x?: T }).x` —— 契约里根本没有这个字段，
   编译过、运行时恒为 undefined，还让人以为能力已接上。验收时 grep 类型断言，命中就问「这字段在类型定义里真存在吗」。
4. **只在「提前校验」的路径上用用户输入，真正的执行点拿不到**：例 —— 把用户配的偏好传给了
   「为了打日志先跑一次」的协商，执行函数内部再协商时没传下去，于是日志说 A、实际跑 B。
   处置：凡是「同一件事算两遍」的地方，逐处确认输入一致；并写一条**只有这个差别能被观测到**的测试
   （例：两种手段都有时点名要后者 —— 默认链会选前者，测不出来就说明测试没用）。
5. **汇报文件空 / 没落盘**：老毛病，不代表没干活。永远以 `git status` + 构建结果为准。
