# 等价变异：登记，不要放水

变异测试跑起来之后，一定会遇到一类**永远杀不死**的变异：代码被改坏了，但对所有输入输出
行为完全相同。典型形态是循环边界 —— `i < n` 换成 `i <= n`，多跑的那一轮读到的值是
`undefined`、比较为假、循环体空转，而循环结束后没人再读 `i`。

这类变异**不是测试缺口**。把它当成缺口去处理，会逼出三种全是负收益的动作：

| 常见动作 | 为什么是错的 |
| --- | --- |
| 调高存活率阈值 | 阈值一旦为等价变异让路，真缺口也跟着被放行，门禁等于半关 |
| 删掉这个变异点 | 清单里少一条，但下一个等价变异还会来；而且删了就不再有人复核它 |
| 加一条「为了杀死它」的断言 | 断言的是一个实现细节（循环变量），源码一重构它就红，且它守不住任何行为 |

## 1. 做法：单独的豁免清单文件

一份 JSON（或同等结构），逐条四个字段，**四个都不能省**：

- `file` / `line` / `label` —— 三者合起来才唯一确定一处候选。只记位置会把同一行的
  另一个候选（`&&`→`||`）一起豁免掉，而那个本该继续参加统计；
- `reason` —— 说清「改了为什么行为不变」。缺 reason 就拒收整份清单。

**清单读不出来或形状不对时整体停手，绝不静默跳过。** 跳过意味着那一批等价变异重新回到
存活分子里，报告会一直顶在阈值边缘，而看报告的人并不知道清单压根没读进去 ——
这比清单写错更难发现。

## 2. 豁免条目必须会过期

登记「这处杀不死」是有期限的结论：周围代码一变，它可能就变得可观测了。

所以匹配到豁免条目之后仍要照常跑测试，并按结果分三路报：

- 还绿 → 豁免成立，**不计入存活分子**（分母也排除，否则会稀释存活率）；
- 变红 → 计为杀死，并标「清单过期」，**这一步要失败**：留着不会让数字失真，
  但下次有人照着清单判断「这处本来就该豁免」时读到的就是过期结论；
- 一次都没匹配上 → 多半是产物行号变了，那处已回到统计里，单独报出来而不是闷声。

三路都要出现在同一份报告里。只给存活数字的报告会被读成「测试写得好」，
而真实原因可能是清单在替一处已经守不住的代码说话。

## 3. 阈值要照实测基线定，不照默认值定

脚本自带的默认值是「还没跑过」时的占位，不是目标值。流程是：

1. 先跑一轮拿基线（抽样**必须是确定的**：产物文件排序 + 包间轮转，别用随机 ——
   随机的抽样让每一次数字都不可比，也就定不出阈值）；
2. 把阈值收到基线之上一点点（给「新出现的、还没登记的等价变异」留一个的余量）；
3. 首红先 triage 存活清单，不先调阈值。

实测一例：三包各 20 个变异，基线存活 0（另有 2 个登记豁免），阈值从默认的 20%
收到 5% —— 20% 意味着放行 4 个假测试。

## 4. 与其它两个 skill 的分工

- `mutation-verify`：单条回归测试的定向验证（撤掉修复看是否变红），成本一分钟；
- `fake-test-audit`：静态排查恒等断言、零断言这类**根本不会失败**的测试；
- 本 skill：规模化跑起来之后，处理「跑不死但不是测试的错」那一批。

三者互补：静态扫不出的「断言写了但没区分两条路径」，靠变异暴露；
变异暴露出来的存活里，有一批是等价的，靠本 skill 的清单收口。
