# 凭据处理

凭据泄漏的路径比想象的多，而且**泄漏时通常毫无症状**（测试全绿、功能正常）。

## 1. 四条硬禁

| 泄漏面 | 为什么危险 | 怎么做 |
|---|---|---|
| **命令行参数** | 同机任何用户 `ps` 都能看到完整命令行 | 走 stdin / 协议内认证 / 临时凭据文件描述符，不拼进 argv |
| **环境变量** | `/proc/<pid>/environ`（或等效机制）能被读到；还会被子进程继承 | 只在**必要**时用，用完即清；能走内存对象就别走环境变量 |
| **临时文件** | 权限设错就是明文落盘；程序崩溃时残留 | 能不落盘就不落盘；必须落盘时用受限权限且用完即删 |
| **日志 / 错误消息 / 结构化字段** | 日志会到处转发、会被贴进工单 | 错误消息里的凭据一律替换为占位符；拼接错误文案时过滤 |

**优先顺序**：内存对象 > 协议内传递 > 管道/文件描述符 > 临时文件 > 环境变量 > argv。

## 2. 具体做法

- 密码只出现在**一条内存对象**里，从解析到使用不外溢
- 需要喂给外部程序时：优先用「程序主动来问、我们通过受控通道答」的方式
  （如 SSH_ASKPASS 助手），而不是预先写进命令行
- 用**文件描述符**传递（进程能读、命令行里看不到），而不是写进临时文件再传路径
- 凭据内存用完要清理；进程退出前确保不留

## 3. 怎么测（这几条测不了就等于没做）

- **断言环境变量里不含密码本体**：起进程后检查它的环境，密码字段必须是**引用**而不是值
- **断言命令行里没有密码**：检查实际 argv（含被包装后的命令）
- **断言错误/告警文本里不含凭据**：把凭据设成一个显眼的字符串，让它走一遍失败路径，
  断言所有输出里搜不到这个字符串
- **断言 dispose 幂等**：清理函数重复调用不抛

## 4. 顺带的纪律

- **连续认证失败可能触发账户锁定** —— 不要自动反复重试；错误提示里要提醒用户
- 私钥权限太开会被拒绝，提示里可以给出具体修法（这是安全侧的正确行为，不是 bug）
- 区分「可复现的实验环境地址」与「真实凭据」：前者写进文档无妨，后者一个字都不行
